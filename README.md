# Event-Driven Notification Service на Go

Практический пример **сервиса уведомлений на Go**, построенного на событийной архитектуре.

Проект показывает, как связать между собой **gRPC, Apache Kafka, PostgreSQL и контейнеризированную инфраструктуру**, чтобы после создания события один сервис мог передать его через Kafka другому сервису для дальнейшей обработки.

Это не просто демонстрация отдельных технологий — репозиторий можно использовать как **готовую учебную основу для изучения событийного взаимодействия микросервисов на Go**.

## Что можно получить из проекта

Изучив и запустив этот проект, вы сможете на практике разобраться:

* как организовать микросервис на **Go**;
* как использовать **gRPC и Protocol Buffers** для взаимодействия между сервисами;
* как передавать события через **Apache Kafka**;
* как организовать взаимодействие по принципу **producer → Kafka → consumer**;
* как отделить создание команды от последующей обработки события;
* как подключить **PostgreSQL** к сервису;
* как запускать Kafka и PostgreSQL в контейнерах через **Podman / podman-compose**;
* как организовать Go-проект с несколькими модулями через `go.work`;
* как генерировать Go-код из `.proto`-файлов;
* как вручную создавать Kafka topic и проверять его состояние;
* как локально запускать и отлаживать сервисы.

## Архитектура

Упрощённо поток данных выглядит следующим образом:

```text
                 gRPC
                  │
                  ▼
        ┌───────────────────┐
        │ Notification      │
        │ Command Service   │
        └─────────┬─────────┘
                  │
                  │ Event
                  ▼
        ┌───────────────────┐
        │   Apache Kafka    │
        │ notifications.    │
        │     created       │
        └─────────┬─────────┘
                  │
                  │ Consume
                  ▼
        ┌───────────────────┐
        │ Notification      │
        │ Processing        │
        │ Service           │
        └─────────┬─────────┘
                  │
                  ▼
             PostgreSQL
```

Основная идея заключается в том, что сервис, создающий уведомление, не обязан напрямую выполнять всю последующую обработку.

Он публикует событие в Kafka, после чего другой компонент может независимо получить это событие и выполнить необходимую бизнес-логику.

## Для чего полезен этот проект

Репозиторий может быть полезен разработчику, который хочет перейти от простых HTTP-приложений к **событийной архитектуре и микросервисному взаимодействию**.

Вместо изучения Kafka, gRPC и контейнеризации по отдельности здесь можно посмотреть, как эти инструменты соединяются в одном прикладном сценарии.

Проект также можно использовать как основу для собственного сервиса уведомлений, например для:

* email-уведомлений;
* push-уведомлений;
* внутренних уведомлений приложения;
* обработки событий регистрации пользователя;
* уведомлений о заказах и платежах;
* фоновой обработки событий.

## Быстрый старт

### 1. Запуск инфраструктуры

Перейдите в директорию с конфигурацией контейнеров:

```bash
cd deployments/docker
```

Запустите Kafka и PostgreSQL:

```bash
podman-compose up -d
```

Проверьте запущенные контейнеры:

```bash
podman ps
```

## 2. Создание Kafka topic

Создайте topic для событий создания уведомлений:

```bash
podman exec -it notify_kafka \
/opt/kafka/bin/kafka-topics.sh \
--create \
--topic notifications.created \
--bootstrap-server localhost:9092 \
--partitions 3 \
--replication-factor 1
```

Проверьте список topic:

```bash
podman exec -it notify_kafka \
/opt/kafka/bin/kafka-topics.sh \
--list \
--bootstrap-server localhost:9092
```

В списке должен появиться:

```text
notifications.created
```

## 3. PostgreSQL

Подключиться к PostgreSQL можно следующим образом:

```bash
podman exec -it notify_postgres psql -U notify
```

Если проект содержит миграции, их можно применить командой:

```bash
podman exec -i notify_postgres \
psql -U notify -d notify \
< 001_init.sql
```

## 4. Генерация gRPC-кода

Перейдите в сервис:

```bash
cd services/notification-command-service
```

Сгенерируйте Go-код из Protocol Buffers:

```bash
protoc \
--go_out=paths=source_relative:. \
--go-grpc_out=paths=source_relative:. \
proto/*.proto
```

В результате из `.proto`-контрактов будут созданы Go-файлы для работы с gRPC.

## 5. Запуск сервиса

Запустите сервер уведомлений:

```bash
cd services/notification-command-service

go run cmd/server/main.go
```

После запуска сервис готов принимать команды и работать с событийным взаимодействием через Kafka.

## Что изучать в первую очередь

Если вы используете репозиторий как учебный пример, рекомендуется двигаться в следующем порядке:

1. Посмотреть `.proto`-файлы и понять контракт gRPC.
2. Изучить точку входа `cmd/server`.
3. Посмотреть, как создаётся событие уведомления.
4. Проследить путь события до Kafka.
5. Посмотреть, как consumer получает событие.
6. Изучить взаимодействие с PostgreSQL.
7. Запустить всю инфраструктуру локально через Podman.
8. Изменить существующий сценарий и добавить собственное событие.

## Кому будет полезен проект

Проект ориентирован прежде всего на Go-разработчиков, которые хотят получить **практический пример событийной архитектуры**, а не только отдельные примеры использования Kafka или gRPC.

Он особенно полезен для изучения:

* микросервисной архитектуры;
* event-driven architecture;
* Apache Kafka;
* gRPC;
* Go workspace;
* PostgreSQL;
* контейнеризации локальной инфраструктуры.

## Итог

**Event-Driven Notification Service** — это небольшая практическая площадка для изучения того, как на Go построить сервис, в котором команды передаются через gRPC, события публикуются в Kafka, а данные сохраняются в PostgreSQL.

Репозиторий можно использовать как учебный пример, основу для экспериментов с Kafka и gRPC или отправную точку для создания собственного событийного микросервиса.
